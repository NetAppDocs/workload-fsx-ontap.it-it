= Replica di una macchina virtuale di storage in un altro file system FSX per ONTAP
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
La replica di una VM di storage su un altro file system FSx for ONTAP in NetApp Workload Factory fornisce un livello protettivo di accesso ai dati in caso di perdita di dati.  Questa operazione replica tutti i volumi in una VM di archiviazione su un altro file system FSx for ONTAP .

.Prima di iniziare
Per replicare una storage VM su un altro file system FSx for ONTAP, devi associare un collegamento. link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["Scopri come associare un collegamento esistente o come creare e associare un nuovo collegamento"^]. Dopo aver associato il link, torna a questa operazione.

.Fasi
. Accedere utilizzando uno dei link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["esperienze di console"^].
. Seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger viene utilizzata per navigare tra carichi di lavoro quali storage, eda, ai, database, vmware e amministrazione."] e quindi seleziona *Archiviazione*.
. Dal menu Archiviazione, selezionare *FSx per ONTAP*.
. Da *FSx for ONTAP*, seleziona il menu delle azioni del file system con la VM di archiviazione da replicare, quindi seleziona *Gestisci*.
. Nella panoramica del file system in VM di archiviazione, selezionare *Gestisci*.
. Nella schermata Gestisci VM di archiviazione, seleziona il menu delle azioni della VM di archiviazione da replicare, quindi seleziona *Azioni avanzate* > *Replica VM di archiviazione*.
. Nella pagina Replica dati, in destinazione replica, fornire quanto segue:
+
.. *FSX per il file system ONTAP*: Selezionare credenziali, area e FSX per il nome del file system ONTAP per il file system FSX per ONTAP di destinazione.
.. *Nome VM di archiviazione*: Selezionare la VM di archiviazione dal menu a discesa.
.. *Nome del volume*: Il nome del volume di destinazione viene generato automaticamente nel formato `{OriginalVolumeName}_copy`.
.. *Criterio di tiering*: Selezionare il criterio di tiering per i dati memorizzati nel volume di destinazione.
+
_Auto_ è la policy di tiering predefinita quando crei un volume nella console di Workload Factory. Per ulteriori informazioni sulle policy di tiering dei volumi, consulta link:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/volume-storage-capacity.html#data-tiering-policy["Capacità di storage dei volumi"^] la documentazione di Amazon FSx for NetApp ONTAP.

.. *Velocità di trasferimento massima*: seleziona *Limitata* e inserisci il limite massimo di trasferimento in MB/s. In alternativa, seleziona *Illimitata*.
+
Senza un limite, le prestazioni di rete e delle applicazioni potrebbero diminuire. Tuttavia, per i file system FSx for ONTAP, ti consigliamo una velocità di trasferimento illimitata per i carichi di lavoro critici, ad esempio quelli utilizzati principalmente per il disaster recovery.



. In Impostazioni di replica, specificare quanto segue:
+
.. *Intervallo di replica*: Seleziona con quale frequenza trasferire gli snapshot dal volume di origine al volume di destinazione.
.. *Conservazione a lungo termine*: Facoltativamente, abilitare gli snapshot per la conservazione a lungo termine.
+
Se abiliti la conservazione a lungo termine, seleziona un criterio esistente o creane uno nuovo per definire gli snapshot da replicare e il numero da conservare.

+
... Per *scegliere un criterio esistente*, selezionare un criterio esistente dal menu a discesa.
... Per *Crea un nuovo criterio*, specificare quanto segue:
+
.... *Policy name*: Inserire un nome di policy.
.... *Snapshot policies*: Nella tabella, selezionare la frequenza del criterio di snapshot e il numero di copie da conservare. È possibile selezionare più criteri di snapshot.






. Selezionare *Crea*.


.Risultato
Tutti i volumi della macchina virtuale di storage vengono replicati sul file system di destinazione.
